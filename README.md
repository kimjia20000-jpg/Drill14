# Drill14 새의 비행 애니메이션

## 구현 목표

bird_animation.png를 이용하여 새 10마리가 날갯짓하면서
화면 안에서 좌우로 반복 비행하도록 구현한다.

## 실행 방법

pico2d와 transitions가 설치된 환경에서 프로젝트 폴더를
작업 디렉터리로 하여 main.py를 실행한다.

## 개발 논리

### 1. 스프라이트 프레임 구성

이미지는 가로 5칸, 세로 3줄로 구성되어 있지만,
마지막 줄에는 새가 4개만 있으므로 실제 프레임은 14개이다.

프레임 번호를 0~13으로 제한하여 마지막 빈칸을 제외한다.
프레임 번호를 5로 나눈 나머지로 열을 구하고,
5로 나눈 몫으로 위에서부터의 행을 구한다.

원본 크기가 918×506으로 칸 수에 정확히 나누어떨어지지 않으므로,
각 칸의 시작과 끝 좌표를 이미지 크기에 비례하여 정수로 계산한다.

pico2d는 이미지 아래쪽을 기준으로 자르기 좌표를 받으므로,
위에서 계산한 칸의 아래 경계를 이미지 높이에서 빼서 변환한다.

### 2. 시간 기반 날갯짓

프레임을 업데이트 횟수마다 1씩 증가시키지 않고,
초당 프레임 수에 game_framework.frame_time을 곱하여 증가시킨다.

초당 14프레임으로 설정하여 한 사이클의 재생 시간을 1초로 정했다.
프레임의 소수 부분은 누적하고, 그릴 때만 정수로 변환한다.
14로 나눈 나머지를 사용하여 애니메이션을 반복한다.

### 3. 시간 기반 이동

이동 거리는 방향 × 초당 이동 속도 × 경과 시간으로 계산한다.
비행 속도는 초당 200픽셀로 설정했다.

이동과 날갯짓 모두 같은 frame_time을 사용하여
프레임 처리 횟수가 달라도 경과 시간에 비례하도록 구현했다.

### 4. 경계 반사와 방향 표현

새의 출력 크기는 100×100이다.
중심 좌표의 이동 범위를 화면 양끝에서 50픽셀 안쪽으로 제한하여
새의 이미지 전체가 화면 안에 있도록 했다.

경계를 넘으면 초과한 거리만큼 반대 방향으로 반사한다.
큰 시간 간격으로 여러 경계를 넘는 경우도 while문으로 처리한다.
경계에 정확히 도착한 경우에도 방향을 안쪽으로 바꾼다.

원본 이미지는 오른쪽을 바라보므로,
왼쪽 이동 시 수평 반전하여 실제 이동 방향과 일치시킨다.
방향이 바뀌어도 현재 애니메이션 프레임은 유지한다.

### 5. 새 10마리와 리소스 관리

서로 다른 Bird 객체 10개를 생성하여 game_world에 등록했다.
각 객체는 자신의 위치, 방향, 현재 프레임을 따로 관리한다.

초기 가로 위치는 화면 너비에 따라 분산하고,
높이는 300, 400, 500을 번갈아 사용한다.
초기 방향은 좌우를 번갈아 지정하고,
날갯짓 시작 프레임도 한 사이클 안에서 분산한다.

이미지는 클래스 변수 Bird.image로 공유하여
같은 이미지 파일을 새마다 중복 로딩하지 않는다.

기존 game_world의 업데이트와 렌더링 순회를 이용하고,
플레이 종료 시 clear()로 등록된 객체를 정리한다.
